1. 헤더 파일과 재컴파일의 필요성

정답: 헤더 파일(.h)이 변경되면 이를 포함하는 모든 소스 파일(.c)은 반드시 다시 컴파일해야 합니다.

이유: #include 문에 의해 헤더의 선언 내용이 컴파일 시점에 소스 코드의 일부로 복사되어 기계어 생성에 직접적인 영향을 미치기 때문입니다.

결과: 다시 컴파일하지 않으면 바뀐 설계도와 기존 기계어 간의 불일치로 인해 링크 오류가 발생할 수 있습니다.

2. Visual Studio 환경 설정 및 트러블슈팅

scanf 보안 에러(C4996) 해결:

파일 최상단(1행)에 #define _CRT_SECURE_NO_WARNINGS를 추가합니다.

또는 프로젝트 속성에서 SDL 검사를 **아니요(/sdl-)**로 설정하여 해결합니다.

프로젝트 관리 규칙:

하나의 실행 파일(.exe) 내에는 반드시 하나의 main 함수만 존재해야 합니다.

여러 실습 파일을 한 폴더에 둘 경우, 실행하지 않는 파일은 빌드에서 제외 처리하여 충돌을 방지합니다.

3. 파일 분할 구성 요약

헤더 파일(.h): 함수의 이름표(원형 선언)를 작성하여 연결 고리 역할을 합니다.

소스 파일(.c): 함수의 실제 본체(정의)를 작성합니다.

메인 파일(main.c): 헤더를 #include 하여 정의된 기능들을 호출하고 전체 흐름을 제어합니다.
